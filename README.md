# Sheetbot

[![tests](https://github.com/DDanga/Sheetbot/actions/workflows/tests.yml/badge.svg)](https://github.com/DDanga/Sheetbot/actions/workflows/tests.yml)

**A Telegram bot that watches a Google Sheet and tells you what matters.**

Notifications when a row crosses a threshold, scheduled reports, and period-over-period
analysis. Any business owner sets the rules up with buttons right inside the bot, with no
code, no cell addresses and no config files.

> 🚧 **Almost there.** Everything is built and tested; the setup guide with screenshots is being
> written. See the [roadmap](#-roadmap).

---

## 💡 What it does

| | Rule type | What it does | Example |
|---|---|---|---|
| 🔔 | **Notification** | Checks every row against a condition | `Stock < Minimum` → "⚠ Milk: 3 left (minimum 10)" |
| 📊 | **Report** | Totals for a period, on a schedule | Every day at 9:00: yesterday's sales by manager |
| 📈 | **Analysis** | Compares periods and ranks products, speaks only when there's something to say | Weekly sales dropped by more than 20% · top products by profit, "hidden stars" |

Rules refer to **column names**, not cell addresses, so inserting or reordering columns
doesn't break them. The full conversation design is in [docs/SCENARIOS.md](docs/SCENARIOS.md).

## 🧪 Demo data

[`template/sheetbot-demo.xlsx`](template/sheetbot-demo.xlsx) is a made-up corner shop with three sheets:
- *Stock*: 15 products with prices and suppliers, 4 of them below their minimum;
- *Sales*: 882 sales from July to October 2026, with an August slump, a bad last week of
  September and a strong October, so every report and analysis has something to show;
- *Clients*: 10 customers.

Upload it to Google Sheets to try the bot without touching real data. The file is generated by

## ▶️ Running

Requires [Python 3.12+](https://www.python.org/downloads/) (tick *Add Python to PATH* when installing).

1. Copy `.env.example` to `.env` and fill in the bot token, the key file and the link to your sheet.
   `POLL_MINUTES` sets how often the sheet is checked (5 by default).
2. Put the Google key (JSON) into the bot folder.
3. **Windows:** double-click `run.bat`. The first run creates a virtual environment and installs
   dependencies, which takes about a minute.
   **Other systems:**
   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   python -m sheetbot
   ```
4. Send `/start` to your bot. The first person to do so becomes the admin; everyone else is
   told the bot is private.

### With Docker

Do steps 1–2, then in the bot folder:

```bash
docker compose up -d      # build and start; it also starts again after a reboot
docker compose logs -f    # see what it's doing
docker compose down       # stop
```

The settings, the key and `data/` stay in the bot folder, exactly as without Docker.

## 🔒 Your data

- **The bot only reads the spreadsheet.** It asks Google for read-only access, so it can't change,
  add or delete anything, even by mistake. Share the sheet with the robot's email as a **Viewer**.
- **Everything it keeps is in `data/` on your computer:**
  - `sheetbot.sqlite`: the people with access (Telegram chat ID, name, role, team, language, pause),
    the rules, reports and analyses, the names of rows it has already reported, and, for
    "changed" rules, a copy of the watched sheet to compare with;
  - `backups/`: a copy of that database for each of the last 7 days;
  - `sheetbot.log`: what happened and when (who was given access, which rule fired, errors).
- **Nothing goes anywhere else.** The bot talks only to Google (to read the sheet) and to Telegram
  (to message the people you let in). No analytics, no third-party services.
- **`.env` and the Google key are secrets.** `.gitignore` keeps them out of git. Anyone with the
  key can read every sheet shared with the robot: if it leaks, delete it in Google Cloud and make
  a new one. A leaked bot token is replaced with `/revoke` in @BotFather.
- **To erase everything**, stop the bot and delete the `data/` folder.

## 🧱 Project structure

```
sheetbot/
├── __main__.py   entry point: settings check, logging, start
├── config.py     reads .env and explains every mistake in plain words
├── sheets.py     reads the Google Sheet (all sheets in one request)
├── storage.py    SQLite: users, roles, language
├── i18n.py       every message in English and Russian
├── rules.py      what a rule is and how it checks a sheet (no Telegram inside)
├── numbers.py    reads "1 234,5 ₽", "1,234.50" or "(300)" as numbers, not "NaN" or "#N/A"
├── builder.py    the rule builder and /rules, all on buttons
├── reports.py    dates, periods, totals, schedule (no Telegram inside)
├── report_builder.py  the report builder, /report and the report schedule
├── analysis.py   period comparison, top items, hidden stars (no Telegram inside)
├── analysis_builder.py  the analysis builder and its schedule
├── access.py     invite links, approval, teams, /users, /pause
├── texts.py      how rules and reports read in messages
├── watcher.py    the background check: new alerts, "back to normal", broken rules
├── common.py     helpers shared by the handlers
└── bot.py        Telegram commands and access checks
tests/            pytest, with fake Telegram and Google (no network needed)
docs/             the conversation design
template/         the demo spreadsheet and the script that makes it
Dockerfile, docker-compose.yml   running in a container
.github/workflows lint, tests on Python 3.12 and 3.13, and a Docker build on every push
```

Run the checks with `pip install -r requirements-dev.txt`, then `ruff check .` and `pytest`.
